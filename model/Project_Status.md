- [x] Phase 1 — Detection core (YOLOv8 on video/webcam, boxes drawn, confidence printed)

- [x] Phase 3 — Simulated geolocation (pixel→lat/lon via altitude+FOV trig, error radius scales with distance from frame center)
- [x] Phase 4 — Priority scoring (weighted: confidence + group size + exposure risk + time-unverified + hazard proximity + immobility → CRITICAL/HIGH/MEDIUM/LOW)
- [x] Immobility scoring — tracks centroid displacement over time, flags "not moving" after a sustained-stillness window
- [x] Thermal detection mode — pretrained thermal-person model (`pitangent-ds/YOLOv8-human-detection-thermal`), tested and confirmed working on real thermal footage
- [x] Fire/smoke detection upgraded from HSV heuristic to pretrained model (`SalahALHaismawi/yolov26-fire-detection`), tested and confirmed detecting fire+smoke on real footage
- [x] Fire/smoke severity scoring reworked — proximity is now relative to frame diagonal (not fixed pixels), fire has a severity floor so any in-frame fire near a person registers as a real hazard, fire weighted heaviest in priority formula (person clearly near fire now correctly scores HIGH/CRITICAL, not LOW)
- [x] Disaster-type architecture (`--disaster-type` flag replacing `--mode`) — only the model(s) relevant to the selected disaster type load and run per frame, via `DISASTER_MODEL_SETS` dict. Cuts CPU load vs. running every model concurrently (95% CPU finding on single-model RGB was the trigger for this change).
  - `fire` → RGB person model + fire/smoke model
  - `flood` → RGB person model + flood/water model (local weights, not yet obtained/tested — see Open Questions)
  - `night` → thermal person model, no hazard model
  - `accident` → RGB person model, no hazard model
- [x] Frame-rate pacing — video files now play back paced to source FPS (skipped for webcam) instead of running unrealistically fast/slow
- [x] End-of-video handling — clean "Footage ended" message instead of silent break
- [x] **Self-trained debris/victim detection model** — fine-tuned YOLOv8n on the VictimDet dataset (harmonious composite victim-in-rubble images, github.com/noahzn/VictimDet) via Google Colab (T4 GPU, free tier). 2,558 training images / 451 held-out validation images (15% split, self-generated since original dataset's val folder was empty). 50 epochs, single class (`person`).
  - **Validation metrics (on composite val set): mAP50 0.995, mAP50-95 0.963, precision 0.997, recall 0.996**
  - **Honest caveat, must not skip this before claiming anything to judges:** these metrics are on synthetic composite images generated by the same harmonization method as training data — not yet validated on real rubble/debris footage. Real-world performance is unverified and could be materially lower. This is the immediate next step, not optional polish.

## Key Decisions Log
- No real drone — video input is webcam/recorded file only, architecture stays drone-agnostic
- GPS is simulated (assumed altitude + assumed camera GPS + trig), always shown with error radius
- No MAVLink/PX4/Gazebo — explicitly out of scope
- SQLite (not PostgreSQL) for hackathon simplicity
- Human verification required before any dispatch — no autonomous action claims
- Never claim detection through walls/rubble — only visible/partially-exposed survivors
- Evidence images: forced 1:1 square crop, 400x400, sharpest-of-8-buffered-frames selection, priority banner burned onto image
- Fire/smoke detection: upgraded from HSV heuristic to a pretrained model (see Completed) — heuristic version fully removed from codebase
- Disaster-type model switching chosen over running all models concurrently, specifically to address measured 95% CPU utilization with even a single extra model running
- Earthquake/debris survivor detection: extensively researched (VictimDet, Post-Disaster-Dataset, RescueNet, various Roboflow options). No public pretrained model existed that was both (a) actually downloadable as local weights and (b) detects partial/exposed victims specifically — so we trained our own via VictimDet's dataset + Colab fine-tuning, rather than either faking the capability or leaving it entirely unaddressed. This is a genuine differentiator IF real-footage validation holds up — must not be presented as validated until it is.
- Model detects single class (`person`) only — does NOT sub-classify into "exposed hand" vs "full body" etc., since VictimDet's dataset/config is single-class. Any such sub-classification claims would be false.
